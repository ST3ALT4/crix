# AGENTS.md — AI Agent Context for CRIX

> Read this file first. It contains everything you need to understand the project without scanning every source file.

## Project Summary

**CRIX (Code Runtime & Input eXplorer)** is a C/C++ code execution visualizer. It takes a C source file, traces its execution step-by-step using a debugger, and produces structured data (variable snapshots, array mutation deltas, call stacks) that will eventually drive animated Vulkan-based diagrams showing how algorithms work (e.g. watching an array get sorted).

**Current state:** The CLI backend is functional. All 4 modes work. The Vulkan visual frontend is not yet started.

## Architecture & Data Flow

```
Input: C source file (e.g. tests/bubble_sort.c)
  │
  ├─► Static Analyzer (libclang)
  │     Parses AST → extracts VarList (name, type, scope, location)
  │
  ├─► Compiler Helper
  │     Auto-compiles source to temp binary with: clang -g -O0
  │
  └─► Runtime Analyzer (DAP protocol via cppdap library)
        Forks lldb-dap as child process, communicates over pipes
        Sets breakpoint at main(), then single-steps through user code
        At each step: queries stack frames, scopes, variables
        Builds ExecutionTrace (vector of StepRecords)
        │
        └─► Report module outputs results as:
              - Terminal table (colored, with delta markers)
              - JSON (structured, for programmatic use)
              - Timeline (step-by-step terminal display)
              - Trace JSON file (for frontend consumption)
```

## Key Data Types

```cpp
// Variable from static analysis
struct VarInfo {
  string name, type, scope_name, value;
  ScopeKind scope_kind;  // GLOBAL, FUNCTION, BLOCK, STRUCT, ENUM
  unsigned line, col;
};

// Runtime value (recursive — can hold arrays/structs)
struct RuntimeValue {
  ValueKind kind;  // PRIMITIVE, ARRAY, STRUCT, POINTER, OTHER
  string type_name, raw_value;
  vector<RuntimeValue> elements;              // array elements
  vector<pair<string, RuntimeValue>> fields;  // struct fields
};

// One step in the execution trace
struct StepRecord {
  int step_number, line, col;
  string file, function_name, stdout_chunk;
  vector<StackFrameInfo> call_stack;
  vector<pair<string, RuntimeValue>> variables;
  StepDelta delta;  // modified_vars + array_mutations vs previous step
};

// The full trace
struct ExecutionTrace {
  string source_file;
  vector<StepRecord> steps;
  string to_json(bool pretty) const;
};
```

## Build System

- **Makefile** — builds with `clang++ -std=c++17`, compiles Slang shaders via `/opt/slang/bin/slangc` into SPIR-V.
- **Dependencies:** libclang, llvm, libdw/libelf, cppdap, lldb-dap, vulkan, glfw3, slangc, imgui.
- **Build:** `make` builds shaders and produces `./crix`.

## Known Issues & Resolved

1. **stddef.h warning:** Static analysis emits `fatal error: 'stddef.h' file not found` — libclang needs `-resource-dir` pointing to `/usr/lib/clang/<version>`. Fix: auto-detect and pass `-resource-dir`.
2. **Globals have no runtime values:** DAP scopes only query Locals/Arguments.
3. **[RESOLVED] char[] display:** Char arrays are formatted as quoted string summaries.
4. **[RESOLVED] DAP banner in stdout:** Filtered OutputEvent to exclude adapter console messages.
5. **[RESOLVED] .gitignore added:** Ignore `.o`, `crix`, `compile_commands.json`, `.cache/`.
